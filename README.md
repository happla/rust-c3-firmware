# Rust ESP32-C3 Embedded Control Firmware

A small embedded firmware project written in Rust for the ESP32-C3 RISC-V microcontroller.

The project explores `no_std` Rust development, state-driven control logic, and workload-based performance-state selection on physical hardware.

## Hardware

- **Board:** Seeed Studio XIAO ESP32-C3
- **Microcontroller:** ESP32-C3
- **Architecture:** 32-bit RISC-V
- **Flash:** 4 MB
- **Debug output:** USB Serial/JTAG

## Technology

- Rust
- `no_std` embedded development
- ESP-HAL
- ESP-IDF-compatible bootloader
- Cargo
- espflash

## Features

### 1. Embedded control state machine

Implements a continuously running control loop using a Rust enum and pattern matching.

The control loop contains four states:

| State | Responsibility |
| --- | --- |
| INIT | Initialise the control system |
| IDLE | Wait for the next control interval |
| MONITOR | Update workload information |
| REPORT | Output diagnostic information |

### 2. Performance-state selection

Implements a simple software policy that selects an operating mode based on a simulated workload value.

| Operating mode | Workload |
| --- | ---: |
| LOW_POWER | 0–29% |
| BALANCED | 30–69% |
| HIGH_PERFORMANCE | 70–100% |

Mode transitions are reported over USB Serial/JTAG.

The workload is synthetic and generated by the firmware for testing the selection logic.

### 3. Hardware execution

The firmware has been compiled, flashed and executed on a physical ESP32-C3 board.

Diagnostic output is transmitted through the integrated USB Serial/JTAG peripheral.

## Building and running

### Requirements

- Rust toolchain
- RISC-V target: `riscv32imc-unknown-none-elf`
- ESP32-C3 board
- USB data cable
- espflash

### Compile

```bash
cargo check
```

### Flash and monitor

```bash
cargo run
```

The Cargo runner is configured to flash the ESP32-C3 and open the serial monitor using espflash.

## Example output

```text
INIT: Control system starting
MODE CHANGE: BALANCED -> LOW_POWER
REPORT: cycle=1 workload=1% mode=LOW_POWER
REPORT: cycle=2 workload=2% mode=LOW_POWER
REPORT: cycle=3 workload=3% mode=LOW_POWER
```

As the simulated workload increases, the firmware selects different operating modes when the configured thresholds are crossed.

## Current limitations

This is an educational embedded firmware project, not a complete SoC power-management implementation.

- Workload values are simulated rather than measured.
- Operating modes are software states; they do not currently change CPU frequency or voltage.
- No thermal monitoring or hardware power management is implemented.
- Automated policy tests have not yet been added.

## Learning objectives

- Develop embedded applications using Rust and `no_std`.
- Understand Rust enums, pattern matching and state machines.
- Cross-compile firmware for a RISC-V microcontroller.
- Initialise and use hardware peripherals through ESP-HAL.
- Implement and observe a simple workload-based control policy.

## Future improvements
